# 图谱语义分层泳道布局 — 设计文档

日期：2026-08-27
状态：待用户审阅
范围：仅前端（`apps/web/src/components/graph/`），不改后端 API 与数据模型

## 1. 背景与问题

当前图谱页（`GraphCanvas.tsx`）使用 G6 v5 **径向布局**：中心节点居中、其余按环展开。
Project / Contract / Party / Commodity / Document 五类节点在环上混杂，业务层级
（项目 → 合同 → 履约单据）不可读。

## 2. 目标结构

画布自上而下固定三个层级，多项目横向并排为独立泳道：

```
 P1 泳道                          P2 泳道
┌────────────────────────────┐  ┌──────────────────┐
│      [项目1]                │  │     [项目2]       │   L0 项目层
│ [主体A][商品B]  [主体C]      │  │    [主体D]        │   ← 侧翼辅助区
│  ├─[合同A1]  ─[合同A2]      │  │  └─[合同C1]       │   L1 合同层
│  │   ├─[单据] │   └─[单据]  │  │      └─[单据]     │   L2 履约层
│  │   └─[单据]              │  │                   │
└────────────────────────────┘  └──────────────────┘
```

- 泳道 = 一个项目的完整子树（含侧翼辅助节点），白卡片容器、按内容自适应宽度。
- 交叉引用（同一单据被多个合同/项目引用）**只归一处放置 + 虚线连线**，不重复渲染节点副本。
- 无任何合同关联的散落单据放入泳道底部「散件」虚线托盘。

## 3. 归层规则（纯函数）

输入现有 `useGraph` 的 `nodes + edges`，不新增后端查询：

| 层 | rank | 归属依据 |
|---|---|---|
| L0 项目层 | 0 | `kind === 'Project'`，每条泳道的锚点 |
| 侧翼辅助 | 0.5 | Party/Commodity，经 party/counterparty/commodity/participates 等边挂到其所属项目 |
| L1 合同层 | 1 | Contract，经 `part_of` 边归属 Project |
| L2 履约层 | 2 | Document，归属"首次引用它的合同"（executes/references/binds 等入边取确定序最靠前者） |

**泛化兜底**：以任意节点为中心查询时图中可能没有 Project（如聚焦某份单据）。
归层按 kind rank 通用化——缺失某一层时，以现存最高 rank 的节点作为伪泳道根，
每个伪根各自成一条泳道。保证双击任意节点重新展开后布局依然成立。

节点只会被分派到一个泳道；跨泳道的边一律保留但仅作连线渲染。

## 4. 定位算法

新文件 `apps/web/src/components/graph/layeredLayout.ts`（纯函数，vitest 可测）：

- 每个泳道内：
  - 项目节点居泳道顶部水平居中；
  - 侧翼辅助节点紧贴项目行下方一行，水平均布；
  - 合同行：该项目的全部合同水平均布；
  - 每份合同的履约单据在其正下方纵向堆叠成一列（多列时合同间留距）；
  - 泳道高度 = 最深列决定，宽度 = max(合同行宽, 单据总列宽) + 内边距。
- 多泳道从左到右排布，间距固定 margin；整体输出 `{nodeId: {x,y}}` 坐标 map +
  泳道包围盒信息（供 Combo 渲染）+ 全局层波段（layerBands，每层的
  {topY,bottomY}，供左侧图层层标尺定位）。
- 跨引用归属判定使用 edges 数组顺序（后端返回序），稳定可复现。
- 常量集中导出（层高、列距、泳道边距），便于调参。

## 5. 视觉方案：「贸易蓝图」克制工程风

沿用应用既有设计语言（纸面浅色、slate 线框、五色 kind 语义色板、PingFang SC），
追求精确、可读、耐看，不做花哨动效堆砌。

### 5.1 画布

- 背景：极浅 slate 底 + 细点阵网格（G6 canvas 插件 grid，低对比度），
  强化"结构图纸"的心智模型。
- 左侧固定**图层层标尺**：L0/L1/L2 三段淡淡的横向分隔虚线 + 竖排小标签
  （项目层 / 合同层 / 履约层），由布局输出的 y 波段计算位置，随画布缩放平移。

### 5.2 节点：圆点 → 圆角卡片

所有 kind 从圆形升级为圆角矩形卡片，左侧竖色条承载 kind 主色，底色用对应 softBg，
描边 1px softBorder（token 全部来自 `businessTypes.ts`，单一来源不变）：

| kind | 形态 | 尺寸基准 |
|---|---|---|
| Project | 实心深紫底、白字、加粗、圆角大卡 | 行首焦点 |
| Contract | 绿 accent 卡片，图标 + 名称两行 | 中号 |
| Document | 藏青 accent 浅底小卡，docType 徽标可选 | 小号 |
| Party / Commodity | 灰蓝 / 琥珀 低饱和紧凑 chip | 更小 |

文案截断沿用 `captionFit` 的弦宽逻辑适配到矩形宽度。

### 5.3 边

- **层级边**（项目→合同→单据）：垂直 smooth cubic，slate-300，宽 1.5，
  hover/选中时加深加粗。
- **交叉引用边**：跨泳道虚线 cubic（#94A3B8），细箭头；
  `binds` 保持现有绿色虚线语言，人工确认关系一眼可辨。
- 边标签默认隐藏（点击选中后在右侧 Inspector 看详情），降低噪音。

### 5.4 动效（克制）

- 首帧 G6 appear 动画：自上而下淡入（短时长，非逐点 stagger）。
- hover：当前节点 halo 高亮 + 相连边提亮、其余元素轻微降透明（focus 效果）。
- 不做布局切换过渡动画。

## 6. 视图交互调整（GraphView）

| 控件 | 处理 |
|---|---|
| 深度(1–5)下拉、方向按钮 | **移除**，分层探索语义下无意义 |
| 项目/合同搜索 | 保留 |
| 图例类型过滤 | 保留（隐藏某类即画布移除该类，泳道自适应重排） |
| 刷新 / minimap / 右侧 Inspector | 保留 |
| 双击节点增量展开 | 保留，复用 `key={center}` 重挂载机制 |
| 绑定工作台跳转联动 | 保留 |
| 图例 | 新增「履约层」说明 |

## 7. 不做的事（YAGNI）

- 泳道折叠/展开、布局算法切换器
- 布局切换动画、暗色模式适配（变量已预留）
- BindingMiniGraph（React Flow 遗留）的任何改动
- 后端/数据模型改动

## 8. 测试策略

- `layeredLayout.ts` 为纯函数 → vitest 单测覆盖：
  归层正确性、首次引用归属、跨引用唯一放置、无 Project 兜底、散件托盘、坐标波段正确性。
- 手动验证：dev server 打开图谱页，核对单项目/多项目/以单据为中心三种场景。
- 完工门槛：build → lint → test 全绿。
