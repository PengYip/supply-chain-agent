# 双分支文档解析管线设计（VLM 直提取 + OCR 文本管线）

日期：2026-08-28
状态：待评审
前置：`docs/superpowers/specs/2026-08-27-execution-materialization-layer-design.md`（履约物化层）、模板类型树 v2（`templateSeed.ts`，spec 2026-08-26 §3.1）

## 1. 背景与问题

现状解析管线是通用文本流程：digital 读取 → 0 块时 MinerU OCR 兜底 → 文本块 → LLM 信息提取，全文落库。该流程对合同类文档正确（需要全文），但对图像原生凭证不合适：

- 汽车过磅单、轨道衡称重记录、水尺计重单等以照片/扫描件到达，无文字层；OCR 对票据/盖章表格恰是最弱路径，而 VLM 端到端提取已实测可靠（`vlmAdapter.ts`，货转单/付款凭证/化验报告三类，注释记载对旋转/印章/合并单元格零错误）。
- 这类凭证业务上**只需要结构化结果**（单车净重、核定卸货量等），不需要全文。
- 现有 VLM 分支按扩展名分流、类型硬编码三类，无法承接新增凭证类型，也没有批量扫描件的工程能力。

样例评估集（`D:\repo\fastchain-agent-demo\example\document-sample`，13 类 33 件）实测结论：

| 实测项 | 结论 |
|---|---|
| 文字层 | 11/13 PDF 无文字层；**两份合同均为纯扫描件**（6-7 页，透印+骑缝章）；数字 PDF 是少数 |
| 汽车磅单 | 针打票据照片拼成 PDF，**一页一车**；最大样本 160 页 35MB；**单据上无合计行** |
| 轨道衡 | 逐车厢表格（28 行×12 列）扫描件/照片，红章压表格，**无合计行** |
| 水尺 | 英文表单（DRAFT SURVEY REPORT）扫描件，目标=核定卸货量，双章压签名区 |
| 铁路运单（火运大票） | 数字 PDF，但**一页一张独立运单**（52 张批量导出） |
| 化验报告 | 照片为主 + 扫描 PDF 混合 |
| 派船通知 | 扫描 PDF 与 docx 混合 |

推论：**总净重在单据上不存在，必须由服务端聚合得出**；"按页拆记录"不是凭证专利（火运大票数字版同样需要）；160 页批量 PDF 要求逐页调用具备并发、单页重试与断点续跑能力。

## 2. 目标 / 非目标

目标：

1. 图像原生凭证（照片、扫描 PDF、照片拼合 PDF）走 VLM 端到端提取，跳过 OCR。
2. 合同类文档保留现有 OCR + 文本管线与全文落库，行为不变。
3. 分类词表对齐模板树，引入"表单类型 → 业务类型"映射层，业务类型调整不改分类器与提取代码。
4. 重量类凭证以总净重正确为第一优先级：行内校验 + 服务端确定性聚合，聚合零幻觉。
5. VLM 不可用时系统整体降级回现状行为（全部 OCR），永不因新组件故障而劣于现状。
6. `example/document-sample` 落地为初始评估集，按类型设验收指标。

非目标：

- 凭证拆单入库（一文件多单据 v1 用单文档 + 明细数组承载，拆分等实际样例驱动）。
- 分类/映射的运营化管理界面（Phase 2 模板管理已有入口，本设计只落数据机制）。
- 火运大票/发票等文本路径提取逻辑的重写（沿用现有 LM 提取，仅补按页拆记录能力）。

## 3. 两层类型模型

```
表单类型（VLM 输出，稳定）      业务类型（模板树 doc_type，可调整）   提取 schema 组
汽车过磅单票据   ─┐
轨道衡称重记录   ─┼─映射→  重量凭证（履约凭证下新中间节点）→ 明细行 + 服务端聚合总净重
水尺计重单       ─┘
化验报告照片     ────→  质检报告/化验报告              → 指标表
银行回单         ────→  付款凭证                       → 金额要素
条款文本扫描件   ────→  合同（route=document）          → OCR + 文本管线
```

- **表单类型**：文档"长得像什么"，由纸质世界决定，清单稳定。VLM 分类器的唯一分类输出（+ 置信度），不直接输出业务类型。
- **业务类型**：模板树 doc_type，履约层 settles/binds 边规则消费对象。调整只改映射，不动分类器与提取代码。
- **映射 = 数据不是代码**：`doc_type.props.formTypes: string[]`，挂在模板表上（与 `aliasOf` 同机制）。VLM 分类 prompt 的表单类型清单由全树 formTypes 并集生成。
- **route 由映射给出**：映射到 合同/立项书/补充合同 → `document`（OCR 分支）；其余 → `voucher`（VLM 分支）。
- **未知表单类型** → 保守默认 OCR 分支 + needs_review；映射表补录即生效，不需发版。

树调整：履约凭证下新增中间节点 `重量凭证`，收编 `汽运磅单`、`轨道衡称重单`（类型 id `dt-汽运磅单` 等不变，边规则 `er-settle-qiyun` 等引用类型名，重挂不受影响），新增叶子 `水尺计重单`。边规则先登记不启用（对齐 Phase 1 惯例），激活与词表归属随 Phase 2 模板管理演进。

样例 → 类型映射：

| 样例 | 表单类型 | 业务类型 | route |
|---|---|---|---|
| 汽车磅单 | 汽车过磅单票据 | 汽运磅单（重量凭证） | voucher |
| 轨道衡 | 轨道衡称重记录 | 轨道衡称重单（重量凭证） | voucher |
| 水尺 | 水尺计重单 | 水尺计重单（重量凭证，新） | voucher |
| 铁路运单 | 火运大票（数字/扫描两形态） | 火运大票 | document（数字）/ voucher（扫描） |
| 化验报告 | 化验报告 | 化验报告 | voucher |
| 银行回单 | 银行回单 | 付款凭证 | voucher |
| 货权转让 | 货权转移证明 | 货转单 | voucher |
| 发票 | 发票 | 发票 | voucher（图片）/ document（数字） |
| 交货确认/交接清单 | 货物交接清单 | 收货单（待业务确认） | voucher |
| 结算单 | 结算单 | 结算单 | voucher |
| 派船通知 | 派船通知单 | 派船通知单 | voucher（扫描）/ document（docx） |
| 合同 | 合同扫描件 | 合同 | document |

注：数字形态的凭证（火运大票数字版、发票数字版）走文本分支但按页拆记录，产出与 VLM 分支同构的 schema 记录——"按页拆记录 → 逐记录提取 → 聚合"是两条分支共享的能力。

## 4. 路由决策树（数据流）

```
文件到达（上传 → MinIO + INGEST_ROOT）
│
├─ jpg/jpeg/png 照片 ────────────→ VLM 凭证提取（渲染免了，直接多图调用）
│
├─ PDF（上传时文字层探测，复用现有 modalityHints 机制）
│   ├─ 有文字层（少数）──────────→ digital 解析 → 现有两阶段分类 → LM 提取
│   │                              （凭证类细类 + 数字形态 → 按页拆记录提取）
│   └─ 无文字层（绝大多数）─────→ 【新】VLM 文档分类（渲染第 1 页小图，一次调用）
│       ├─ document / 低置信 / 失败 → MinerU OCR → 现有文本管线（全文保存）
│       └─ voucher + 已知表单类型 → 【新】VLM 凭证提取（渲染全部页 → 逐页/小批调用）
│
└─ docx/txt 等 ─────────────────→ digital 解析（现状）
```

分类调用输出：`{ formType, confidence }`（route 与业务类型由映射表派生，分类器不感知）。

## 5. 组件设计

| 组件 | 职责 | 边界（不做什么） |
|---|---|---|
| `pdfRender.ts` | PDF 页 → JPEG/PNG（纯 JS 方案，`pdf-to-img`/pdfjs 系；DPI≈150 起步实测校准）；分类取第 1 页，提取取全部页 | 不做 OCR，不碰图片文件 |
| `vlmClassifier.ts` | 1 页图 → `{formType, confidence}`；prompt 含全树 formTypes 清单 + 各类型判别特征（票据抬头+毛皮净→过磅单；多行车号表格→轨道衡；DRAFT SURVEY→水尺；条款文本+骑缝章→合同） | 不输出业务类型，不提取字段，不做路由决策 |
| `vlmAdapter.ts` 泛化 | 单图 → 多图（`image_url` 数组）；schema 注册表按业务类型做键（扩展 `VOUCHER_SCHEMAS`）；按表单类型注入版式提示 | 不做路由，不聚合 |
| `pageRecords.ts` | 按页拆记录 + 有界并发 + 单页独立重试 + 断点续跑 + 服务端聚合 | 不调模型，纯编排 |

现有 `parseDocument.ts` 保持纯解析原语不动；路由逻辑加在其调用方（`documentEntry.ts` 的 ingestFile 分流处），与现有 modality hint 接法一致。

### 5.1 凭证 schema（按凭证组组织，重量组为骨架样板）

重量凭证组共用骨架（汽运磅单/轨道衡称重单/水尺计重单）：

- 明细行数组（磅单：每页一行 `{编号, 卡号, 车号, 毛重_吨, 皮重_吨, 净重_吨, 毛重时间, 皮重时间, 称号}`；轨道衡：逐车厢行 `{车型, 车号, 毛重_吨, 皮重_吨, 净重_吨, 票重_吨, 盈亏_吨}`；水尺：核定要素 `{船名, 航次, 泊位, 卸货量_吨, 检测日期}`）。
- 行内校验：`毛重 − 皮重 = 净重`（磅单/轨道衡，容差 0.01）；轨道衡另验 `净重 − 票重 ≈ 盈亏`。
- 文档级投影：`总净重_吨 = Σ 明细行净重`（服务端确定性计算，**不是模型输出**）。
- 复用 `validateVoucher` warnings 机制：校验失败只降置信、进 needs_review，不硬失败。

其余组：货转/资金/质检沿用现有三个 schema；新增结算单、发票（图片）等按同模式扩展注册表。

### 5.2 批量 PDF 工程约束（160 页样本驱动）

- 逐页独立调用（磅单每页即完整单据；轨道衡以数据行为单位逐行提取；无跨页上下文需求——跨页断裂行属边缘情况，行校验不通过即落 needs_review，不静默丢行），有界并发（并发度实测标定，起步 3-4）。
- 单页失败独立重试（复用现有"错误回灌重试 1 次"模式）；仍失败标记该页 needs_review，**不废掉整文件**。
- 处理进度按页记账（docId + page → status），中断后可续跑；全部页终态后统一聚合。
- 图片 ≤10MB/张、jpg/png 限制沿用；渲染产物按 DPI 控制在限内。

## 6. 误分类防护与降级链

误判代价不对称：凭证误走 OCR 只是慢（文本分类器还会重新给出正确细类，等于自愈）；合同误走 VLM 提取会丢全文。所有默认值偏向安全方向：

- 分类失败 / 超时 / 低置信 / 未知表单 → 默认 OCR 文档分支。
- VLM 提取中发现合同/长文本特征 → 输出路由纠正信号 → 回退 OCR 分支重走。
- route=voucher 但业务类型无注册 schema → 落 `其他` + needs_review。
- 整体降级：VLM 不可用 = 完全回到现状行为（全部 OCR）。

## 7. 数据落库

- 凭证型文档：`documents` 照常建档（docType = 业务类型），不产 blocks/chunks/向量；提取结果 JSON + 字段置信度 + 页级状态入库——沿用现有图片凭证落库模式，扩展类型。
- 聚合产物（总净重等）与校验 warnings 一并入库，供履约层 settles/binds 消费（锚点投影沿用 `extractAnchors` 扩展）。
- 原文件永远在 MinIO/INGEST_ROOT，随时回溯——"不存全文"的安全垫。
- 文档型：现状不变（blocks/chunks/向量）。

## 8. 评估集与验收指标

- `example/document-sample` 13 类 33 件作为初始评估集；文件不入库（体积/license），评估时从本地路径读取（与 `.mineru.json` hermetic 模式同思路），复制入 `apps/server/eval/fixtures/` 由 .gitignore 排除或以清单文件引用本地路径（实施期定）。
- 分类：路由正确率（document/voucher 二分）+ 表单类型正确率。
- 磅单/轨道衡：**总净重准确率（第一指标）** + 逐行字段准确率 + 行校验通过率。
- 水尺：核定卸货量准确率。
- 合同：全文转写质量（对照 MinerU 基线，chunk 可用性不回归）。
- 工程：160 页样本端到端可完成、单页故障不扩散、断点续跑有效。
