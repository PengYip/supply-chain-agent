# 验收手册：本体图谱投影与穿透（P1-P4 全量）

日期: 2026-09-09
适用: main @ `219ca68` 之后的所有部署（dev 10.10.0.2 已含）
范围: 本体事实/关系登记 → 图谱投影（同步图谱）→ 跨空间穿透 → 凭证据源 → 台账关系核对

## 一、样例准备

设计成一个**背靠背购销 + 预付 + 核销 + 红冲 + 服务费分摊**的连贯故事，样例间可互相勾稽。单据用电子 PDF 或清晰扫描件，关键字段必须肉眼可读（要过 OCR/解析）。

### 最小集（6 份，跑通主链）

| # | 样例 | 关键字段要求 | 喂给哪个环节 |
|---|---|---|---|
| 1 | 采购合同 PDF | 合同号 `HT-CG-2601`、供方「唐山XX钢铁」、需方（我方）、品名（如 热轧卷板 Q235B）、数量 500 吨、金额 190 万、签订日期 | 解析→确认→合同台账→文档图谱 |
| 2 | 销售合同 PDF | 合同号 `HT-XS-2601`、卖方（我方）、买方「河北XX建材」、同品名、数量 500 吨、金额 197.5 万 | 同上 |
| 3 | 收货单（或磅单） | 日期、品名、数量 500 吨 | 绑定→六向流水→文档图谱 |
| 4 | 发货单 | 数量 500 吨 | 同上 |
| 5 | 增值税销项发票（蓝字）PDF | 发票号、金额 100 万（故意只开一部分） | 事件登记 |
| 6 | 付款回单（银行电子回单） | 付款 30 万、收款方=供应商、日期、用途「预付货款」 | 凭证据源主角 |

### 进阶集（4 份）

| # | 样例 | 用途 |
|---|---|---|
| 7 | 收款回单（客户回款 60 万） | CollectionEvent + 核销 |
| 8 | 物流费发票 + 付款回单（1.5 万，第三方物流公司） | ServiceCostEvent + 分摊 |
| 9 | 一份 5-8 页混排扫描 PDF（合同+收货单+磅单连排） | 批量拆分 → 单据组 CONTAINS 谱系 |
| 10 | 红字发票（也可省略：用对话登记负数事实代替） | 红冲溯源 |

### 纯文本准备（不需要单据）

己方主体名称、供应商/客户/物流公司全称、商品名+规格。

## 二、前置动作（约 5 分钟）

1. **全程使用同一个测试账号**登录 `http://10.10.0.2:3001`（数据按用户隔离，换账号互不可见）。
2. 左侧「本体」→ 台账：主数据抽屉登记 1 个商品（品名+商品码）、2-3 个交易对手（供应商/客户/服务商）；己方主体在主数据区名单抽屉登记。
3. 图谱 tab 工具栏点一次**「同步图谱」**做基线。预期提示"已投影 N 节点 / M 边"；若提示"图谱未配置"说明环境 Neo4j 有问题，先停下排查。

## 三、验收场景

### 场景 1：文档图谱基线（既有能力回归）

| 操作 | 预期 |
|---|---|
| 拖拽上传合同 1、2 到对话 → 解析 → 审阅工作台核对 → 确认 | 合同进入台账（合同投影来自 contract_ledger） |
| 「本体」→ 图谱 tab，搜 `HT-CG-2601` | 合同节点 + 对手方/单据邻域（交易方/履行边） |
| 绑定工作台：收货单绑定采购合同 | binds/settles 语义入图，六向流水生成 |
| 「项目」视图做归属确认 | 项目树可见 项目→合同→单据 |

### 场景 2：事件登记（对话 + 表单双入口）

| 操作 | 预期 |
|---|---|
| 台账「付款事件」→「登记事件」表单：填回单信息（含「来源单据」`documentId` 填回单的 docId）→ 提交 | 生成工单号 → 审批中心批准 → 台账出现该行；详情抽屉字段表底部显示**「来源单据」**行 |
| 对话："登记一笔 2026-06-25 的 30 万元预付付款，付给唐山XX钢铁，来源单据 `<回单docId>`" | 同上走审批；`documentId` 可在台账列表行/穿透图 Document 节点复制 |
| 台账「发票事件」→ 表单登记蓝字发票（100 万，正向） | 审批后可见 |

### 场景 3：核销与冲抵（工作台，整单守恒）

| 操作 | 预期 |
|---|---|
| 「核销工作台」：30 万预付对蓝字发票做**部分核销** | 余额 30/100、状态 partial；台账发票详情「本体关系」区出现**核销**边（含金额参数） |
| 故意提交超额分配 | **整单拒绝、零边产生**（守恒拦截负例） |
| 登记一笔结算事件后切「冲抵」模式：预付冲抵结算 | 冲抵边落库；付款详情可见**冲抵结算**边 |

### 场景 4：关系登记（对话，本期 P4 新入口）

先在台账复制相关事实 id（TF- 开头），然后逐条对话：

| 话术 | 预期 |
|---|---|
| "把 `<服务费TFid>` 这笔服务费分摊 15000 元到合同 `HT-CG-2601`，方式按金额" | 审批批准后落 **ALLOCATE_TO** 边；服务费详情「本体关系」区显示"分摊 → HT-CG-2601（金额 15,000）" |
| "红字发票 `<红票TFid>` 冲的是 `<蓝票TFid>`，冲 10 万，原因 开票有误" | 落 **REVERSE_ORIGIN** 边；蓝票详情时间线出现红冲行（红标），**净额自动轧差为 90 万** |
| "红票冲蓝票但方向写反/金额带错参数再试一次" | 整单拒绝并返回原因（连接对白名单/strict params 拦截负例） |
| （可选）"`<收货TFid>` 是 `<结算TFid>` 的结算依据" 等 | FEEDS_INTO / CORRESPONDS_TO / TRIGGERS / PROVIDE 同款登记 |

注意：核销（WRITE_OFF）和冲抵（OFFSET_SETTLE）对话里不受理，模型应引导去核销工作台——这是设计如此。

### 场景 5：红冲净额轧差（依赖场景 4 的 REVERSE_ORIGIN 边）

蓝字发票详情：时间线含红冲行（红标"逆向"）、净额 = 100 万 − 10 万 = **90 万**；切换「当时口径」到红冲前日期，净额回到 100 万（as-of 切片）。

### 场景 6：图谱投影 + 穿透（P1/P2/P3 核心验收）

先点一次**「同步图谱」**（把场景 2-4 的存量数据收敛进图），然后在图谱 tab：

| 操作 | 预期 |
|---|---|
| 以 30 万付款事件为起点穿透 | **「凭证溯源」边**直连付款回单（Document 节点）；双击逐跳 |
| 以服务费为起点穿透 | **分摊边 → 合同 → 名下单据** 一屏到底（跨空间逐跳） |
| 以蓝字发票为起点穿透 | **核销边**（悬停显示金额）连付款；红冲溯源边连红票 |
| 台账任一事实详情 →「在图中查看」 | 跳入穿透并以该实体为中心 |

### 场景 7：批量拆分谱系（进阶）

上传混排 PDF → 批量拆分 → 确认单据组。预期：穿透里收货单节点带「文档血缘」边（悬停显示页码/序号）连到单据组。

## 四、快速检查单

| # | 检查点 | 交付 | 通过标准 |
|---|---|---|---|
| 1 | 事件/主数据登记走审批，批准后台账即时可见 | 既有 | 台账出现，字段一致 |
| 2 | 表单/对话登记均支持来源单据 | P3 | 详情抽屉显示「来源单据」行 |
| 3 | 「同步图谱」三态反馈 | P1 | "已投影 N 节点 / M 边" |
| 4 | 穿透「凭证溯源」边 | P3 | 事件 ↔ 原始单据直连 |
| 5 | 穿透跨空间（本体→合同→单据） | P2 | 分摊链一屏到底 |
| 6 | link_ontology 六种关系对话可登记、走审批 | P4 | 落边 + 详情「本体关系」可见 |
| 7 | REVERSE_ORIGIN 方向/参数校验负例 | P4 | 方向反/多余参数整单拒绝 |
| 8 | 红冲时间线净额轧差 | P4+既有 | 净额 90 万；当时口径回 100 万 |
| 9 | 核销余额/部分核销/超额整单拒绝 | 既有 | 余额口径正确 |
| 10 | 单据未确认时同步不报错 | P3 | skippedEvidence 计数，不算失败 |

## 五、已知边界（不是 bug）

1. **图是投影**：审批通过即自动投影；但存量数据、图故障期间漏投的、或直接改库的数据，要点「同步图谱」收敛（幂等可反复点）。失效事实下次同步自动出图。
2. **核销/冲抵只走工作台**：对话里这两类会被引导到核销工作台（整单守恒需要结构化整单提交，设计如此）。
3. **收/发货事件双源**：单据确认而来的收发"事件"在台账与穿透里以单据（Document）表示，登记源（TF id）才是事件节点——两类并存是口径设计。
4. **documentId 靠登记时提供**（对话说清或表单粘贴），暂无"从单据自动抽取事件"的管线——单据→事件的自动化属后续路线。
5. **数据隔离**：事实/关系按用户隔离（共享 `''` 行全可见）；Neo4j 事件节点带 userId prop。

## 六、排障速查

| 症状 | 第一动作 |
|---|---|
| 穿透图缺边/缺节点 | 点「同步图谱」，看返回的 skippedEvidence / failures |
| 「凭证溯源」边没出现 | 检查登记时是否带了 documentId；单据是否已确认（未确认会被跳过，确认后重新同步补上） |
| 穿透血缘整层缺失（提示"文档血缘不可用"） | 环境问题：dev 服务器 NEO4J_PASSWORD / neo4j 容器状态 |
| 合同穿透为空 | 合同号归一化不匹配（桥接按 normalizeName）；核对台账合同号与单据上合同号 |
| 审批后台账没出现 | 审批中心确认是否真的批准；同一测试账号 |
