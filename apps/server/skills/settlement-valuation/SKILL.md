# 货值计算（暂估与结算）

大宗商品的货值分两个阶段：

1. **暂估**：化验/质检报告出具之前，按实际发运重量与合同**基准价**估算货值。
2. **结算**：质检报告出具之后，按实际质量指标对基准价做**奖罚修正**，得到最终结算货值。

## 阶段 A：暂估（化验前）

1. 查合同约定：用 query_business(entity="contract", contractNo=...) 取合同台账，
   找到**基准单价**（数量与单价的约定）；条款细节（计价基准、扣水扣杂约定）用
   recall_documents 传 contractNo 加条款关键词（如"价格/基准/单价"）取原文，引用 document_id。
2. 查实际重量：用 recall_documents（或 gather_settlement_evidence 的执行流水）
   找**重量单据**（磅单/轨道衡/水尺），确定已发运数量。多张重量凭证时以结算口径
   为准（勿把预告凭证与实重凭证双计，以 gather_settlement_evidence 返回的
   executionProgress.delivered 为权威）。
3. 计算并展示：
   暂估货值 = 实际发运重量 × 合同基准价
   分步展示：重量（来源单据 document_id/flowId）→ 基准价（条款出处）→ 算式 → 结果。
4. 明确告知用户这是**暂估值**，质检报告出具后需按质量奖罚修正。

## 阶段 B：结算（质检报告出具后）—— 固定四步

**第一步：查合同约定。** query_business(entity="contract") 拿台账字段；
recall_documents 检索质量条款原文（关键词如"质量/奖罚/热值/硫分/水分/扣罚"），
确认：基准指标、奖罚规则（每偏差单位的加减价）、上下限、计价基准。

**第二步：查实际单据。** 先调 gather_settlement_evidence（一次给齐：合同条款原文、
执行流水与权威交付量、质量凭证的化验指标、历史结算）。数量单据不足或质量凭证缺失时，
回到 recall_documents 按单据类型关键词补查；仍缺则走"缺口处理"。

**第三步：按规则计算。**
- 结算数量 = executionProgress.delivered（勿逐行累加流水，会双计）。
- 逐项计算质量奖罚：对每个约定指标，偏差 = 实际值 − 基准值，
  调整额 = 偏差 × 单位奖罚额（有上下限先截断），每项单独列出算式与依据。
- 结算单价 = 基准价 + Σ 调整额；结算货值 = 结算数量 × 结算单价。
- 每个数字必须标注来源（flowId/extractionId/document_id），不得出现无出处的数字。

**第四步：输出计算书并向用户确认。** 计算书格式：

```
结算计算书（合同 <contractNo>）
一、规则依据：<条款摘要，每条附 document_id>
二、数量依据：<重量凭证 + flowId，结算数量=X 吨>
三、质量依据：<质检报告 extractionId，指标值...>
四、计算过程：
    基准价 = ... 元/吨
    <奖罚项1> = (...) = ±... 元/吨
    结算单价 = ... 元/吨
    结算货值 = X 吨 × ... 元/吨 = ... 元
五、结论：暂估 ... 元 vs 结算 ... 元，差额 ...
```

用户明确确认后，调用 confirm_settlement 落结算台账（数量/单价/奖罚明细/依据 id
与计算书完全一致）。确认前不得调用。

## 缺口处理

- **无质检报告**：只能出暂估值，如实说明"质检报告未出具，暂按基准价暂估"，不得替造指标。
- **奖罚条款无法解析**（条款缺失/表述歧义）：不得自行脑补规则，调用 escalate_to_human
  生成工单，说明缺口（缺哪份单据/哪条条款）。
- **重量凭证冲突**：以 gather_settlement_evidence 的 executionProgress 口径为准，
  并在计算书中说明取舍理由。
- 一切数字来自工具返回（数字零幻觉硬约束），本技能只规定"怎么算与怎么呈现"。
